## Target
- `backend/app/routers/sessions.py` — `put_session_manifest` (lines 183–204)

## Expected Safe Behavior (`docs/7_API_Documentation.md` Section 5.1, lines 870–871; `docs/10_Test_Cases.md` TC-API-17)
Per `docs/7_API_Documentation.md` (`/sessions/{session_id}` description):
> "A capture with `has_image` false (image lost on the phone) needs no upload, so the session can still complete."

When a session manifest is accepted and all listed captures have `has_image: false` (`missing_images: []`), no `PUT /sessions/{session_id}/captures/{capture_id}/image` requests can ever follow (uploading an image for a `has_image: false` capture is rejected with `409 IMAGE_NOT_EXPECTED`). Therefore, when `missing_images` is empty upon manifest ingestion, the session must immediately transition to `status = "COMPLETE"` with `completed_on = today` so that phone reconciliation (`GET /v1/sessions/{session_id}`, `docs/7_API_Documentation.md` Section 5.4) confirms the server holds the completed session.

## Actual Behavior (Evidence)
In `backend/app/routers/sessions.py` lines 183–185:
```python
missing_uuids = [c.capture_id for c in body.captures if c.has_image]
initial_status = "RECEIVING"
completed_on = None
```
`initial_status` is unconditionally set to `"RECEIVING"` with `completed_on = None` even when `missing_uuids` is empty (`[]`). Because no capture in the session has `has_image = True`, `put_capture_image` can never be called for this session, leaving the session permanently stuck in `RECEIVING` with `completed_on = null`. Phone reconciliation (`GET /v1/sessions/{session_id}`) never sees `status == "COMPLETE"`, blocking local retention cleanup and export completeness.

## Steps to Reproduce
1. Start the disposable breaker environment and seed study `SKP-BRK`, test site `SKP01`, an enrolled device, and participant `SKP-0001`.
2. Submit `PUT /v1/sessions/{session_id}` with one capture where `has_image: false`, `image_sha256: null`, `image_size_bytes: null`.
3. Observe response and subsequent `GET /v1/sessions/{session_id}`: `missing_images` is `[]`, yet `status` is `"RECEIVING"` and `completed_on` is `null` forever.
